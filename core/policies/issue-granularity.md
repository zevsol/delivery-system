# Issue 粒度政策

Issue 以可独立交付、验证和评审的结果划分，而不是以页面、模块或文件数量划分。一个 Issue 可以修改多个文件，但必须只服务于一个主要结果。

停止拆分的最低条件：结果单一；验收标准明确；依赖清楚；职责边界相关；失败可定位；不需要等待整个 Epic 才能验证；未知技术风险已处理或明确阻塞。

以下情况必须拆分或先创建 Spike：存在多个独立用户结果；使用“以及/并且”连接不相关目标；跨越多个不相关职责；L/XL 工作项的风险或验证边界不清；关键技术未知会影响方案。

Issue 模板至少包含背景、目标、范围、非目标、实施约束、依赖、验收标准、验证方法、Definition of Done 和关联产物。文件操作只能作为 Issue 内部 Checklist，不能伪装为独立价值。
