# 审查严重度模型

严重度表达交付风险，而非审查者偏好。每个 Finding 都必须用证据解释等级。

| 等级 | 含义 | 默认处理 |
|---|---|---|
| blocker | 不解决即无法安全进入下一质量门，或关键决定/证据完全缺失 | 阻塞受影响工作，要求用户决定或修复 |
| high | 高概率导致范围、架构、交付或验证失败的重大缺口 | 在批准或执行前处理，除非用户明确接受风险 |
| medium | 重要但可局部处理的完整性、追踪、验收或维护问题 | 进入计划或 Change Request，并明确 owner |
| low | 不影响当前关键闭环的改进项 | 记录、排序或延期 |
| note | 信息、观察或非强制建议 | 不要求修复或用户接受 |

审查者不得仅因偏好、命名风格或未证明的推测赋予 blocker/high。证据不足时应使用 note 或明确标注需要进一步调查。
