# Execute Delivery Core Workflow

> 适用角色：Execute Delivery
>
> 关联权威：`../CORE-CONTRACT.md`

## 目的

在不改变已批准产品意图的前提下，实现无阻塞、Implementation Ready 的 Issue，并提供可复查的完成与验证证据。

## 执行前检查

开始前必须确认：Issue 状态允许执行；依赖已完成或满足条件；关联 Requirement、ADR 与验收标准可访问；工作区状态已检查；不存在未解决 blocker；预计修改范围与 Issue 一致。

任一关键条件不满足时，必须停止受影响部分并报告 Blocked Issue，不得通过自行解释产品意图绕过条件。

## 执行规则

1. 先调查现有实现、约束和用户已有改动，再修改。
2. 在 Issue 范围内小步实现，保留不相关的用户改动。
3. 为验收标准选择并运行适用验证；不能运行时如实记录原因与风险。
4. 更新与实现直接相关的技术文档和追踪证据。
5. 将范围外发现记录为 Change Candidate、Defect 或 Technical Discovery，而不是顺手实现。
6. 对删除、发布、外部写入或其他不可逆操作请求用户批准。

## 范围外发现

发现新需求、显著架构变化、额外用户能力、重大测试范围扩大或依赖变化时：暂停受影响部分 → 记录候选事项 → 返回 Idea to Delivery 影响分析 → 等待用户决定 → 更新基线和 Issue 后再继续。

## 完成报告

完成报告必须包含：改动摘要、关联 Issue、每条验收标准的验证结果、已运行测试、未验证内容、直接更新的技术文档、剩余风险和 DoD 结论。执行者不得自行宣称产品验收或发布批准已完成。
