# 常见问题

## 这是不是代码生成器？

不是。它首先是交付治理工作流；只有 Execute Delivery 在已批准 Issue 范围内协助实现。

## 为什么不能直接让 Auditor 修文档？

因为审查与修复分离，才能保留独立证据和用户的最终决定权。

## 为什么会生成 Change Request？

新能力、范围扩张、架构变化和显著测试扩大需要显式影响分析，避免静默破坏已批准基线。

## 我只想修一个小问题，也要完整 PRD 吗？

不需要。小修复可使用 Brief → Issue → Verification 的轻量流程。

## 现在支持哪些平台？

Core 平台无关；当前只有 OpenAI/Codex Adapter 已实现。其他平台对接目前已搁置；如未来恢复，仍须先在各自官方规范中验证后才可实现。
